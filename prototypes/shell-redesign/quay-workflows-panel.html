Quay Workflows Panel

The Workflows module holds three engines: Archon runs (with the spec tasks it reads), the Machina Factory's work orders, and the way into the Praxis Builder stage tab. Today Archon and the Factory are each a full-window modal, and the Builder has no button at all. Here are four ways to lay them out in a 230 to 300 px panel, with the companion and stage tabs.         My recommendation

        B · By state, detail right

        • It is the rule you approved for the Agents panel: lists in the panel, the one thing you picked beside the terminal in the companion. Nothing covers the terminal while you approve a run or clear a hold.
        • The panel is sorted by what you have to do, not by which engine did it. An Archon approval, a Factory hold, a failed run and a Praxis decision all land in one Needs you list at the top, each row naming the action it waits on (Approve, Resume, Hold, Merge, Browser).
        • Every run and work order folds to the same three-line row: engine letter and name, status and spend, and a segment bar with one segment per Archon node or Factory stage. You read progress across all three engines the same way.
        • Start holds what you launch: pinned Archon workflows as one-click chips, the spec's open tasks with an Agent button, recent Praxis graphs (each opens the Builder tab on it), and New work order. The Factory switch, Halt and today's spend sit in a strip at the top.
        • A run's graph and log at full width slide over the terminal as a lens, the way the diff lens does for a pull request.

        The cost: the companion gains a third view (Run, beside Pull request and Activity), and picking a run with its own terminal also selects that terminal. In my own run of the job, following the outline, A and B took 9 clicks, D 10, and C 12, because C starts most steps with a tab. A ties B on clicks but opens a stage tab over the terminal for every run you look at.
