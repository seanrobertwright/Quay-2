        My recommendation

        B · Lane on each terminal row

        • Yes, the Projects module gets the pipeline, but not as a new place. A ticket that is being worked has a terminal, and the Projects panel already lists terminals. So each terminal row grows a second line: its ticket (from the ticket and pull request slots you approved) and a four-step lane, Ticket · Terminal · Pull request · Merged, coloured by state.
        • Tickets with no terminal yet sit under the terminals in two short lists: Ready to start, each row with an Implement button, and Blocked, each naming its blocker. Each list shows three, then a "+N more" link into Source control.
        • A merged ticket's terminal keeps showing Merged until a new signal arrives (the rule you approved), so the lane ends in place. Tickets merged today with no terminal show in a folded Merged today count.
        • From a lane you can: pick the terminal (the companion follows), Implement a ready ticket, and open a ticket without a terminal in the companion. Merge, comment and close stay in the companion, where the readiness card is.
        • Nothing covers the terminal, plain shells keep their one-line row, and the module bar and its status dots do not move.

        The cost: terminal rows double in height, so about 12 fit in the panel instead of about 20, and the Projects panel scrolls sooner. In my own run of the job, following the outline, B and C took 5 clicks, A and D 7. C ties on clicks but takes 86 px off every terminal, all the time.
